Algorithms and data structure performance characteristics are analyzed using asymptotic Big-O notation.

Time and Space Complexity Fundamentals:
- Constant Time O(1): An algorithm whose execution time remains strictly constant regardless of input size N. Examples include accessing an array element by index or looking up a key in a hash table with no collisions.
- Logarithmic Time O(log N): Typical of divide-and-conquer algorithms. Binary search on a sorted array achieves O(log N) worst-case time complexity, dividing the search interval in half with each comparison. Binary search does not have O(N^2) complexity.

Sorting Algorithms:
- MergeSort: A divide-and-conquer sorting algorithm that divides the array into halves, recursively sorts them, and merges the sorted halves. MergeSort has a guaranteed worst-case, average-case, and best-case time complexity of O(N log N).
- QuickSort: A partitioning sorting algorithm. QuickSort has an average-case time complexity of O(N log N). However, if an unbalanced pivot is chosen repeatedly (such as on an already sorted array without random pivoting), QuickSort degrades to a worst-case time complexity of O(N^2). QuickSort does not have a guaranteed O(N) complexity across all cases.

Data Structures:
- Hash Tables: Implement an associative array abstract data type using a hash function to compute an index into an array of buckets. Under uniform hashing, hash tables provide average-case O(1) time complexity for insertion, lookup, and deletion.
- Binary Search Tree (BST): A node-based binary tree data structure. When balanced, search operations run in O(log N) time. However, when degenerate or completely unbalanced (e.g. elements inserted in sorted order forming a linked-list structure), BST search degrades to worst-case O(N) linear time complexity. A basic BST cannot guarantee O(1) lookup.
